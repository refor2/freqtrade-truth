# Freqtrade Truth 0.1.0: public numerical-candidate contract

**Scope:** universal, read-only, local-user-configured Python audit library.
**Release decision:** candidate-only API, not a certification or statement of
financial performance. This contract does not depend on any specific operator
account, private bot, key or infrastructure. Users supply their own read-only
access to whichever supported source they choose.

## Contract boundaries

1. The immutable `NormalizedTradeRecord` uses UTC close times, explicit
   canonical instrument and settlement currency, and `Decimal` money fields.
   `None` means unknown, **never zero**; zero requires observed evidence.
   Components are signed from account-equity perspective (paid fee/funding
   negative, received rebate/funding positive).
2. The core `group_comparable_records` discovers *candidate* associations by
   exact instrument and currency and an explicit UTC close-time tolerance.
   Source-local IDs and timestamp proximity cannot prove ownership. Ambiguous
   multi-bot groupings remain review, not assigned to a guessed trade.
3. `reconcile_group` statuses describe **numerical comparison only**:
   `match` = every requested known field is within the inclusive Decimal
   tolerance; `review` = a known outside-tolerance difference or structural
   multiple-bot ambiguity; `incomplete` = missing source record or field
   without a known mismatch. Known differences take priority over unknowns.
   All missing fields remain `None`; no missing-as-zero or implicit FX.
4. Financial component delta is **exchange minus Freqtrade** in the same
   native currency. A reported net already including fees/funding must
   **not** be summed with those components again. The standalone exact
   position/settlement ledger may reconstruct a *native* signed net only from
   unique independent event components and explicitly declared coverage.
   Coverage declared in a local input is not independent account proof.
5. Reports expose `numeric_status` separately from
   `identity_status=unverified` and
   `financial_truth_status=unverified`. Flags such as
   `verified_trade_identity`, `verified_account_financial_truth`,
   `funding_ownership_verified`, `usd_valuation_verified` remain false
   unless a separately reviewed, genuinely independent future proof-bearing
   contract supports them. Never equate USDC and USD by assumption.
6. `reconcile-okx` and `reconcile-bybit` are **bounded source comparisons**
   with private local credentials; results remain candidates. Any malformed,
   contradictory, incomplete, repeated or truncated source read must fail
   closed or remain explicitly unverified. A numeric match is not an
   authenticated cross-system trade ownership claim.
7. No trade entry, modification, withdrawal or account mutation calls are
   present. Credentials are read from the operator's local environment only.
   No real API keys, fills, personal account records, logs or private bot
   identifiers enter source code, public CI or release archives.
8. Default reports redact source IDs and amounts. An explicit local
   reveal option must never be used to publish confidential evidence.

## What 0.1.0 does **not** promise

- Verified lifetime PnL, historical exchange retention completeness, balance,
  taxes or certified accounting;
- authoritative Freqtrade ↔ exchange fill/position ownership;
- account-level attribution of every funding event, especially shared-symbol
  events or legitimate empty source windows;
- historical USDC-to-USD conversion without source event-time FX evidence;
- support for every exchange, instrument type, account mode or OS environment.

These are optional further capabilities, not reasons to secretly upgrade a
candidate result to a proof or to block this universal local library.

## Operator installation

Install the reviewed wheel/sdist in an isolated Python environment; configure
supported exchange and Freqtrade credentials through **local environment
variables or local secret stores only**. For example `OKX_READ_API_KEY`,
`OKX_READ_API_SECRET`, `OKX_READ_API_PASSPHRASE`, and optional
`FREQTRADE_READ_USERNAME`, `FREQTRADE_READ_PASSWORD`. Read permissions
must be constrained by the operator. Do not place secrets in config examples,
GitHub, Actions, command arguments, URLs, screenshots or public logs.

Run `freqtrade-truth --help`, `freqtrade-truth demo --json`, and the
appropriate local read-only command. A demo passes synthetic checks only.
A successful remote GET proves a response, **not** full account ownership.

## Compatibility and change policy

Python 3.11–3.14 under tested CI. The report format explicitly separates
candidate numerical matches from economic truth. Additional certified
financial-truth verdicts require an independent signed-source evidence
review, coverage and provenance matrix, separate examples and migration
notes. Existing core numeric statuses retain their old meaning.
Historical proposals remain in [v0.1-contract-review.md](v0.1-contract-review.md)
for transparency.
